# 授课讲义管理系统 · 项目资料展示

高校授课讲义的分级审核与归档系统：教师按课程组提交讲义 → 课程负责人 / 教学秘书 / 教务处处长 / 教学院长逐级审批 → 文档归档至 ECM 内容平台 → 全校按角色与学院权限分级查阅。实习期间的企业项目，本人独立负责需求到交付。

> **仓库性质**：业务系统构建于网易 CodeWave 低代码平台（应用主体在平台内，不随仓库分发），本仓库存放**可迁移的工程技术资产**：需求文档、搭建任务书、集成经验沉淀、数据库结构与自研 Java 扩展组件源码。

## 项目速览

- **交付周期**：7 周单人交付——需求会议、PRD 5 轮迭代、3 轮原型评审，到低代码搭建、联调、上线
- **规模**：8 个功能页面、7 张自建业务表、5 节点审批流、8 类角色 / 4 级数据权限
- **集成**：从鸿翼 OpenContent ECM 的 298 个开放接口中筛选 16 个完成对接（SSO 免登、目录授权、分块上传、版本管理）；教务库 10 张表只读直连（跨数据源查询）

## 技术亮点

- **自研 Java 上传扩展组件**（`hongyi-file-uploader/`，v1.0.8）：低代码平台无法将 multipart 文件流转发给外部服务，自研平台扩展组件接管上传链——本地暂存校验 → 分块上传 ECM → 返回文件引用回写业务表；打包为平台可导入的扩展包，供审批上传链调用。
- **SSO 免登与密钥安全**：MD5 签名互信登录，ECM 密钥托管在服务端配置、不下发到前端；6 级目录树常驻授权（学院 / 角色到目录的映射账本方案）。
- **接口筛选与集成方法论**：对 298 个开放接口按"业务动作 → 候选接口 → 联调验证"三轮收敛到 16 个；枚举核对 + 日志留痕规范保障批量导入零返工。
- **数据权限建模**：8 类角色 × 4 级数据范围（全校 / 学院 / 课程组 / 个人）在低代码平台的表达式权限体系中落地。
