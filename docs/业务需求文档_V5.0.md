## 一、业务全景（一句话）

**教师按课程组提交授课讲义 → 课程负责人三维度审核 → 教学秘书审核 → 教务处处长（只读）审核 → 教学院长审批 → 全校按角色分级查阅。文件存鸿翼（课程级共享 + 选课号级专属两级上传），CodeWave 低代码开发，数据源直连教务系统。**

```
┌─────────────┐   CodeWave 数据源直连   ┌────────────────────┐   鸿翼API(V1.5)   ┌──────────────┐
│  教务系统    │ ────────────────────→ │  CodeWave 本系统     │ ──────────────→ │  鸿翼OpenContent│
│ (<内网地址·已脱敏>│                         │  (应用标识 jygl)     │                  │ (文件/上传/预览)│
```

## 二、角色与四级权限（V1.5 五节点对齐）

| 角色 | 数据范围 | 核心动作 | 过滤字段 |
|------|---------|---------|---------|
| 授课教师 | 仅本人提交的讲义组 | 提交讲义（课程组）、查看进度、驳回后重提、撤回 | `teacher_id` = 登录人 |
| 课程负责人 | 所负责课程的全部讲义组 | 三维度审核（通过/驳回） | `leader_id` = 登录人 |
| 教学秘书 | 本学院开课内容 | 审核（通过/驳回）、"无需提交"标记维护 | `teaching_college` = 登录人学院 |
| 教务处处长 | **全校** | 只读审核（通过/驳回），意见必填 | 校级角色（无学院过滤） |
| 教学院长 | 本学院开课内容 | 审批（流程终点），意见必填 | `teaching_college` = 登录人学院 |
| 学院书记 | 本学院开课内容 | 查阅（不参与流程） | `teaching_college` = 登录人学院 |
| 教务处（校机关） | **全校**（裁判：谁交了/谁没交） | 监督，**不参与审批** | 无过滤（全校） |
| 校领导 | 全校 | 宏观查阅 | 无过滤（全校） |

> ✅ 称谓与职责按 V1.5 决策调整：V4.0"教学副院长"统一更名"**教学院长**"（终点，客户书面确认）；"教务处处长"为审批链节点③（**只读**审核）；"教务处（校机关）"仍为监督裁判角色，两者是不同对象。
> ✅ 会议纪要"教务处不参与审批、仅裁判监督"——在**校机关层面**仍成立，落实为教务处处长参与审批 + 教务处（校机关）提供全校列表监督。

## 三、核心业务流程（主链路，组粒度）

```
① 教师登录 → 讲义总览（首页）：本人本学期【课程组】列表
     （待提交组 = 教务选课号按(学期,课程)聚合 − 已有组记录 − 无需提交标记 − 已软删选课号）
        ↓
② 点击"提交"→ 提交申请页（课程组维度）
   预填：学年学期/课程编号/课程名称/开课学院/授课教师
   选课号明细清单：默认全选（有效选课号），可反选；逐个展示行政班
        ↓
③ 上传文件 → 鸿翼两级上传（课程级共享文件 → L5 教师工号目录；选课号级专属文件 → L6 教学班序号目录按需创建）→ 回写 fileId
        ↓
④ 提交 → ① 写 jygl_lecture_group 组表（冗余课程/学期/学院 + leaderId/leaderName）
        ② 写 jygl_lecture_group_item 明细（每个选中选课号一行）
        ③ 写 jygl_material_file（groupId + roundNo + itemId 可空；itemId 为空 = 课程级共享文件）
        ④ launch 流程 2.0（业务数据 = 组实体；流程变量 leaderName）
        ⑤ updateBy 回写 processId → 组状态 = 待课程负责人审核(0)，明细状态同步
        ↓
⑤ 课程负责人审核（三维度 + 明细只读可见）→ 通过 → 待教学秘书审核(1)
⑥ 教学秘书审核 → 通过 → 待教务处处长审核(2)
⑦ 教务处处长审核（表单全只读 + 同意/驳回）→ 通过 → 待教学院长审批(3)
⑧ 教学院长审批（终点）→ 通过 → 已通过(4)
   ※ 任一节点"通过" = 组内全部选课号明细逐条置为对应状态（通过即全部子级通过）；
     任一节点驳回 → 整组回开始节点，组状态 = 已驳回(5)，教师修改后整组重提（roundNo+1）
        ↓
⑨ 已通过后可对单个选课号"单独修改"→ 拆组（新组独立走完整审批流）
```

### 状态机（组级 auditStatus，6 值）

| 值 | 状态 | 迁移条件 |
|----|------|---------|
| 0 | 待课程负责人审核 | 提交/重提后 |
| 1 | 待教学秘书审核 | 负责人通过 |
| 2 | 待教务处处长审核 | 教秘通过 |
| 3 | 待教学院长审批 | 教务处处长通过 |
| 4 | 已通过（终态） | 教学院长通过 |
| 5 | 已驳回 | 任一节点驳回，整组回开始节点 |

- "**已撤回**"不作独立状态值（客户确认保留撤回）：撤回 = 调 withdrawTask（下一节点未处理时可撤）+ 组记录 isWithdrawn 标记，组状态复用"待提交"侧逻辑，不占 auditStatus、不增轮次；重提后 isWithdrawn 清零。
- 明细级仅两个独立标记：`isUnsubmit`（无需提交，教秘维护）、`isInvalid`（选课号被教务软删后置 1，仅展示用，不参与统计）。
- 终态统一命名"**已通过**"；V4.0"已备案/已归档"表述废止。

## 五、审批流程设计（流程 2.0，五节点）

| 节点 | 审批人 | 表单权限 | 审批意见 | 可见内容 |
|------|--------|---------|---------|---------|
| 开始 | 发起人（教师） | 全部可编辑 | - | - |
| 审批任务① | **流程变量 leaderName**（课程负责人） | 可修改 | 选填；驳回必填 | 组信息 + 选课号明细（只读）+ 三维度勾选 + 文件预览 |
| 审批任务② | **流程逻辑动态查人**（该学院教学秘书，或签） | 可修改 | 选填；驳回必填 | 组信息 + 明细 + 文件预览 |
| 审批任务③ | 校级角色（教务处处长） | **全只读** | 选填；驳回必填 | 组信息 + 明细 + 文件预览 |
| 审批任务④ | **流程逻辑动态查人**（该学院教学院长，或签） | 可修改 | 选填；驳回必填 | 组信息 + 明细 + 文件预览 |
| 唯一分支 | - | 驳回 → 整组回开始节点；通过 → 下一节点 | - | - |

**已确认机制（V1.5）**：
- 审批人指定：① 负责人 = 流程变量 `leaderName`（"工号:姓名"= userName 格式）；②④ 教秘/教学院长 = 流程逻辑产生（输入开课学院 teachingCollege → 查该学院具有教秘/教学院长职务的人员 → 输出 userName 列表，多人逗号拼接或签）；③ 教务处处长 = 校级角色配置（全校唯一，无动态过滤）
- 驳回：**整组回开始节点 + 改状态**（流程实例存活、processId 不变、审批历史自动完整）；不支持退回上一节点（V1.5 明确，如客户提出可用 revertTask 评估）
- 评论：**平台流程评论组件承载**（嵌套在流程记录中，随流程实例存储），**无需自建评论表**；正式意见仍走审批意见字段（approveTask/rejectTask 的 comment 入参）
- 待办：任务箱组件（自动获取当前用户待办）+ curApprover 列表可见性（保留）；负责人待办 = 该课程下所有教师提交的组（leaderId 过滤天然覆盖）
- 审批详情弹窗：复用 `leaveManageProcessQuery` NASL（getProcInstInfoByInstId + getProcInstRecordsByInstId）
- 登录体系：模板框架 currentUser，userId = employee_id，userName = "工号:姓名"
