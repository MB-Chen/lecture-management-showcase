## 一、现有实现的三个漏洞（本次要修的）

主人贴的现有 `removePersonPermission`：

```nasl
identityId = app::logics::getIdentityIdByAccount(app::logics::hyGetToken(undefined), employeeId);   // ← 第 1 次登录
allFolders = sql"SELECT folderId FROM JyglHyFolderMap WHERE level IN (1,2) AND isDelete = 0";
for (folderItem in allFolders, index in 0) {
    ...
    apiResult = apis::jyglyc::interfaces::s880b67f94...(
        Body = ...Body { token = app::logics::hyGetToken(undefined),   // ← 每轮再登录一次！
                         folderId = Convert<Integer>(folderItem), mermbers = delList });
    if (apiResult.result != 0) { result = s"移除失败：${apiResult.result}"; end; }   // ← 一轮失败整体中止
}
result = '移除成功！';
```

| # | 漏洞 | 后果 | 修法 |
|---|---|---|---|
| **1** | 🔴 **不查就删**（主人指出的核心） | 该人本来无权限也照发 N 次删除请求；返回码含义不明（"删了"还是"本来就没有"），结果文案不可信 | **先 `LoadFolderPermission` 逐目录查**，只对 `entryId == 本目录`（direct）的命中项发删除 |
| **2** | 🔴 **token 在循环里重复登录** | `hyGetToken` **每次都真·集成登录**，且鸿翼「同账号再登立刻作废前一个 token」⇒ 一轮一登、前面全废；N 个目录 = N+1 次登录，**慢且会顶掉同页其它操作** | **循环外取一次** `tok`，全程传参复用（token 铁律：用时现取、往下传参） |
| **3** | 🔴 **扫的范围是 `level IN (1,2)`，漏掉 L4** | 项目实际授权主体是**课程 L4 目录**（09-09 定论：授 L4 才能覆盖该课全部教学班）⇒ 现有清权**根本清不掉真正的逐课授权** | 扫描范围参数化：`scope='all'` 覆盖到 L4；纯 L4 清理走附录的**定向清**（更快） |

另有两处小问题：
- 循环内 `if (apiResult.result != 0) { ... end; }` —— **一轮失败就整体中止**，剩下目录没清、文案只反映第一个失败。改为**累计失败信息，跑完再返回**。
- `permCateId` **写死 9** —— 若该人某目录实际是 `cateId=8`（仅预览），用 9 去删可能匹配不上。修法：**把查出来的真实 `permCateId` / `permType` 带过去删**（见 §六 ①）。

## 二、四接口总览（契约定稿）

| # | 逻辑名 | 入参 | 出参 | 语义 |
|---|---|---|---|---|
| ① | `getPersonPermissions` | `employeeId : String`（工号）<br>`scope : String = 'resident'` | `result : String`（JSON） | **查某人有哪些目录授权**（只报 direct 命中，标注继承项） |
| ② | `addPersonPermission` | `employeeId : String`<br>`folderId : String`（单个目录 id）<br>`permCateId : Integer = 9` | `result : String` | **给某人授某目录权限**（先查，已有则幂等跳过） |
| ③ | `removePersonPermission` | `employeeId : String`<br>`scope : String = 'resident'` | `result : String` | **移除某人权限**（先查 direct → 只删命中项；无命中直接返回） |
| ④ | `getSystemPermissions` | 无（可选 `scope`） | `result : String`（JSON） | **系统可授权清单**：目录树 + 权限类别，供管理端下拉/勾选 |

**关于"userId"的口径**：鸿翼内部用的是数字 `identityId`，而 CodeWave 侧对外一律用**工号**（= `employee_id` = `currentUser.userId`，与 `removePersonPermission` / `grantResidentL1/L2` 完全一致）。所以四个接口的入参统一是**工号**，接口内部用 `getIdentityIdByAccount` 转 `identityId`，调用方不需要知道鸿翼 id。✅ 与既有三接口口径一致，不引入新概念。

### 2.1 与需求原文逐条对照（09-10 20:32 复核）

> 需求原文（主人 09-10）：① 这个人有什么权限，输入 userId ② 给某个人添加什么权限，输入 userId、**权限 body** ③ 给某个人移除权限，输入 userId ④ 整个系统有什么权限，用于选择赋予某个人

| # | 需求原文 | 本次实现 | 对上没 |
|---|---|---|---|
| ① | 这个人有什么权限 ← userId | `getPersonPermissions(employeeId, scope='resident')` → `result`(JSON) | ✅ |
| ② | 给某人添加权限 ← userId + **权限 body** | `addPersonPermission(employeeId, **folderId**, permCateId=9)` | ✅ **已定稿**（09-10 20:32 主人拍板）：口径按「单个 folderId」走，"body" 的语义由「一次一目录」承载，批量交给调用方循环 |
| ③ | 给某人移除权限 ← userId | `removePersonPermission(employeeId, scope='resident')` | ✅ |
| ④ | 整个系统有什么权限（供选择赋予某人） | `getSystemPermissions(scope='resident')` → 目录清单 + 权限类别 | ✅ |

**三处需要知悉的差异（都不是错，是取舍）**

1. ✅ **② 的入参口径 —— 已拍板（09-10 20:32）：保持「单目录」**（`employeeId + folderId + permCateId`）。需求原文说的"权限 body"，其语义由「**一次调用 = 一人一目录一权限**」承载；**批量由管理端在调用方循环调用本接口**，服务端保持原子。原设计理由（§五 开头已写）：
   - ① 语义清晰、可审计（一条调用 = 一次授权）；
   - ② **规避 CodeWave「循环内不能调逻辑」红线** —— 批量授权就得循环，而循环里没法调 `grantFolderPermission`；
   - ③ 管理端勾多目录时，**在调用方循环调本接口**即可，服务端保持原子。
   - ⛔ 已否决的替代方案：入参改成 `body` 权限数组 → 服务端必须**在循环内直接调鸿翼接口**（`NewSetFolderPermission`），不能用现成逻辑，改动量与风险都更大（详见 §六 ⑤ 的写法）。若日后确需服务端批量，再加一个 `addPersonPermissions`（数组入参）的**独立**接口，不动本接口。
2. 🟡 **每个接口多一个可选 `scope`**（`resident` = L1/L2 秒级 / `all` = 含 L3/L4 可能超时）。因为有默认值 ⇒ **调用方只传工号也能跑**，不违反"输入 userId"；不需要就直接删（③ 的删法见 §六 6.2 下方 💡）。
3. ➕ **额外多做了第 5 个逻辑** `removePersonPermissionOnCourse`（附录 A）：定向清某人在某门课 L4 的授权，**不属于**这四接口，是补充能力（因为逐课 L4 全扫会超时，必须定向清）。

### 🔴 判 direct / 继承的判据（这是「先查后删」的关键）

`LoadFolderPermission` 返回 `data.permissions[]`，每条含：

| 字段 | direct（可直接删） | 继承（不要删） |
|---|---|---|
| **`entryId`** | **== 所查 `folderId`** | 指向**权威目录**的 id（别的目录） |
| `inheritPath` | 空 / null | 如 `企业内容库\讲义管理\计算机学院` |
| `state` | `0` | `1` |

> ⚠️ **以 `entryId == folderId` 为准**（09-09 实测铁证），`state` / `inheritPath` 只作旁证。
> 继承项不要对它发删除请求 —— 删 direct 那处，继承自然消失；对继承项发删也删不动。

### 其他行为

- 目录**本来无人授权** → `result:0` + `permissions` 空数组，**不是错误**（这正是"无权限"的正常返回）。
- `folderId` 无效 → `801`（文件夹不存在）。
- 只查 `data.permissions`，**忽略 `data.hiddenPermissions`**。

## 四、接口① `getPersonPermissions`（查某人有什么权限）

### 4.1 NASL 参考

```nasl
using nasl::core;
using nasl::collection;
using nasl::util;

@(description = '查询某人在鸿翼目录上的直接授权（先查后删的基础；开放为接口）')
logic getPersonPermissions(employeeId: String, scope: String = 'resident') => result: String {
    let tok;                                   /* ★ 只登一次，全程复用 */
    let identityId: List<Integer>;
    let idInt: Integer;
    let scanFolders;                           /* SELECT folderId → List<String> */
    let folderItem: String;
    let permResp;                              /* LoadFolderPermission 响应 */
    let permList;                              /* permResp.data.permissions */
    let hitCount: Integer = 0;
    let json: String = '';
    let sep: String = '';
    let hit: app::structures::HyPermHit;
    let hitList: List<app::structures::HyPermHit> = []: List<app::structures::HyPermHit>;

    tok = app::logics::hyGetToken(undefined);
    identityId = app::logics::getIdentityIdByAccount(tok, employeeId);
    if ((!HasValue(identityId)) || (Get(identityId, 0) <= 0)) {
        result = s"{\"code\":1,\"msg\":\"解析人员失败:${employeeId}\"}";
        end;
    } else {
    }
    idInt = Get(identityId, 0);

    /* 扫描范围：resident = L1应用 + L2学院（常驻授权范围，约十余条，秒级）
                   all      = 再加 L3学年 + L4课程（逐课授权落在这里，条数可能上百，慢） */
    if (scope == 'all') {
        scanFolders = sql"SELECT folderId FROM JyglHyFolderMap WHERE isDelete = 0 AND level IN (1,2,3,4)";
    } else {
        scanFolders = sql"SELECT folderId FROM JyglHyFolderMap WHERE isDelete = 0 AND level IN (1,2)";
    }
    if ((!HasValue(scanFolders)) || (Length(scanFolders) <= 0)) {
        result = s"{\"code\":2,\"msg\":\"目录映射表无数据\"}";
        end;
    } else {
    }

    /* 逐目录查权限，只收「direct 命中该人」的项 */
    for (folderItem in scanFolders, index in 0) {
        permResp = apis::jyglqxcx::interfaces::s<LoadFolderPermission接口id>(
            token = tok,
            folderId = Convert<Integer>(folderItem),
        );
        if (permResp.result == 0) {
            permList = permResp.data.permissions;
            if ((HasValue(permList)) && (Length(permList) > 0)) {
                for (p in permList, i in 0) {
                    /* 只认：本人 + 个人授权 + entryId==本目录（direct） */
                    if (((p.memberId == idInt) && (p.memberType == 1)) && (p.entryId == folderItem)) {
                        Add(hitList, app::structures::HyPermHit {
                            folderId = folderItem,
                            permCateId = p.permCateId,
                            permType = p.permType,
                        });
                    } else {
                    }
                }
            } else {
            }
        } else {
            /* 单个目录查询失败（如 801）→ 跳过，不要 end，否则一个坏目录毁掉整体 */
        }
    }

    /* 拼 JSON（不依赖 join，用 sep 控制逗号） */
    for (h in hitList, i in 0) {
        hitCount = hitCount + 1;
        json = s"${json}${sep}{\"folderId\":\"${h.folderId}\",\"permCateId\":${h.permCateId},\"permType\":${h.permType}}";
        sep = ',';
    }
    result = s"{\"code\":0,\"employeeId\":\"${employeeId}\",\"identityId\":${idInt},\"scanned\":${Length(scanFolders)},\"count\":${hitCount},\"permissions\":[${json}]}";
    end;
}
```

**配套新结构体**（在 `app::structures::` 下建，供 ①③ 共用）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `folderId` | String | 目录 id（库里是 VARCHAR） |
| `permCateId` | Integer | 该人在这条目录上的**真实**权限类别（8/9/12…） |
| `permType` | Integer | 10=分配权限 / 20=流程权限 |

### 4.2 返回样例

```json
{"code":0,"employeeId":"41255","identityId":1208,"scanned":15,"count":2,
 "permissions":[{"folderId":"161","permCateId":9,"permType":10},
                {"folderId":"296","permCateId":9,"permType":10}]}
```

> 若要带**目录名**给管理端直接显示：把扫描 SQL 改成 `SELECT * FROM JyglHyFolderMap WHERE ...`（见 §九 坑 5），
> 在循环里用 `v.pathKey` 一并塞进 `HyPermHit`（再加一个 `pathKey : String` 字段）即可。

### 4.3 拖组件蓝图

```
[开始]
  ├─【变量】tok / identityId(List<Integer>) / idInt / scanFolders / folderItem / permResp / permList
  │        / hitCount=0 / json='' / sep='' / hit(HyPermHit) / hitList(List<HyPermHit>)=[]
  ├─【调用逻辑】hyGetToken(undefined) → tok                ★ 循环外，只此一次
  ├─【调用逻辑】getIdentityIdByAccount(tok, employeeId) → identityId
  ├─【If】!HasValue(identityId) 或 Get(identityId,0)<=0 → result=失败JSON【End】
  ├─【赋值】idInt = Get(identityId, 0)
  ├─【If】scope == 'all' →【SQL】level IN (1,2,3,4) → scanFolders
  │   【Else】           →【SQL】level IN (1,2)     → scanFolders
  ├─【ForEach】folderItem ∈ scanFolders
  │     ├─【调用接口】LoadFolderPermission(token=tok, folderId=Convert<Integer>(folderItem)) → permResp
  │     ├─【If】permResp.result == 0
  │     │     └─【赋值】permList = permResp.data.permissions
  │     │        【ForEach】p ∈ permList
  │     │           └─【If】p.memberId==idInt 且 p.memberType==1 且 p.entryId==folderItem
  │     │                 └─【Add】hitList ← {folderId, permCateId=p.permCateId, permType=p.permType}
  │     └─【Else】空（单个目录查询失败静默跳过）
  ├─【ForEach】h ∈ hitList → 拼 json 串、hitCount+1
  └─ result = 完整 JSON
[结束]
```

> 🔴 **循环内只「调用接口」，不「调用逻辑」**（CodeWave 红线）。所以 `Convert<Integer>`、`Add` 这类内建操作可以放循环里，`app::logics::xxx` 不行。

## 五、接口② `addPersonPermission`（给某人添加权限）

> **入参为什么是「单个 folderId」而不是「权限 body 数组」**：① 语义清晰（一次一人一目录，可审计）；
> ② **规避"循环内不能调逻辑"红线**——批量就得循环，而循环里没法调 `grantFolderPermission`；
> ③ 管理端勾选多目录时，在**调用方**循环调本接口即可，后端保持原子。
> （若一定要在服务端批量，见 §六 ⑤ 的"循环内直接调接口"写法。）

### 5.1 NASL 参考

```nasl
using nasl::core;
using nasl::collection;
using nasl::util;

@(description = '给指定工号授某鸿翼目录的预览下载权限（先查后授，幂等；开放为接口）')
logic addPersonPermission(employeeId: String, folderId: String, permCateId: Integer = 9) => result: String {
    let tok;
    let identityId: List<Integer>;
    let idInt: Integer;
    let fid: Integer;
    let permResp;
    let permList;
    let already: Boolean = false;
    let curCate: Integer = 0;
    let permItem: apis::jyglyc::structures::newPermissions;
    let newPerms: List<apis::jyglyc::structures::newPermissions> = []: List<apis::jyglyc::structures::newPermissions>;
    let changeItem: apis::jyglyc::structures::newPermissions;
    let changePerms: List<apis::jyglyc::structures::newPermissions> = []: List<apis::jyglyc::structures::newPermissions>;
    let apiResult;

    /* 参数校验：folderId 必须是数字串，否则 Convert<Integer> 直接抛错 */
    if ((!HasValue(folderId)) || (Length(folderId) <= 0)) {
        result = '参数错误：folderId 为空';
        end;
    } else {
    }

    tok = app::logics::hyGetToken(undefined);
    identityId = app::logics::getIdentityIdByAccount(tok, employeeId);
    if ((!HasValue(identityId)) || (Get(identityId, 0) <= 0)) {
        result = s"解析人员失败:${employeeId}";
        end;
    } else {
    }
    idInt = Get(identityId, 0);
    fid = Convert<Integer>(folderId);

    /* ★ 先查：该目录该人是否已有 direct 授权，且类别是什么 */
    permResp = apis::jyglqxcx::interfaces::s<LoadFolderPermission接口id>(
        token = tok,
        folderId = fid,
    );
    if (permResp.result == 0) {
        permList = permResp.data.permissions;
        if ((HasValue(permList)) && (Length(permList) > 0)) {
            for (p in permList, i in 0) {
                if (((p.memberId == idInt) && (p.memberType == 1)) && (p.entryId == folderId)) {
                    already = true;
                    curCate = p.permCateId;
                } else {
                }
            }
        } else {
        }
    } else {
        /* 查询失败（如 801 目录不存在）→ 直接拒绝，不要"盲授" */
        result = s"目录查询失败：folderId=${folderId}，鸿翼返回 ${permResp.result}";
        end;
    }

    /* ② 已有且类别相同 → 幂等跳过 */
    if (already && (curCate == permCateId)) {
        result = s"已授权，跳过：${employeeId} → ${folderId}（当前 cate=${curCate}）";
        end;
    } else {
    }

    /* ③ 已有但类别不同 → 走 changePermissions 升级/降级（如 8 仅预览 → 9 预览+下载） */
    if (already && (curCate != permCateId)) {
        {
            changeItem.memberId = idInt;
            changeItem.memberType = 1;
            changeItem.permCateId = permCateId;
            changeItem.permType = 10;
        };
        Add(changePerms, changeItem);
        apiResult = apis::jyglyc::interfaces::s<NewSetFolderPermission接口id>(
            Content_Type = undefined,
            Body = <...>Body {
                token = tok,
                folderId = fid,
                changePermissions = changePerms,
            },
        );
        if (apiResult.result == 0) {
            result = s"权限已变更：${employeeId} → ${folderId}（${curCate} → ${permCateId}）";
        } else {
            result = s"变更失败：鸿翼返回 ${apiResult.result}";
        }
        end;
    } else {
    }

    /* ④ 原先没有 → 新增授权 */
    {
        permItem.memberId = idInt;
        permItem.memberType = 1;
        permItem.permCateId = permCateId;
        permItem.permType = 10;                    /* 🔴 必须显式赋 10，否则序列化成 null → 鸿翼 400 */
    };
    Add(newPerms, permItem);
    apiResult = apis::jyglyc::interfaces::s<NewSetFolderPermission接口id>(
        Content_Type = undefined,
        Body = <...>Body {
            token = tok,
            folderId = fid,
            newPermissions = newPerms,             /* 🔴 字段名是 newPermissions，本应用若被建成 permissions 会静默失败 */
        },
    );
    if (apiResult.result == 0) {
        result = s"授权成功：${employeeId} → 目录${folderId}（cate=${permCateId}）";
    } else {
        result = s"授权失败：鸿翼返回 ${apiResult.result}";
    }
    end;
}
```

### 5.2 为什么"先查"对添加也重要

- 鸿翼 `NewSetFolderPermission` 对**同人同目录同类别**重复写虽然幂等，但会**刷新授权时间戳**、也会写操作日志；管理端反复点会刷出噪声。
- 更关键的是**类别升/降级**：先查才知道该走 `newPermissions`（新建）还是 `changePermissions`（改），
  否则想从 8 升到 9 时若只传 `newPermissions`，可能生成第二条记录或原地不动（视鸿翼实现），结果不可预期。

### 5.3 拖组件蓝图（关键分支）

```
[If] folderId 空 → 拒绝【End】
[调用逻辑] hyGetToken → tok            ★ 循环外一次
[调用逻辑] getIdentityIdByAccount(tok, employeeId) → identityId
[If] identityId 空/<=0 → 失败【End】
[赋值] idInt=Get(identityId,0) / fid=Convert<Integer>(folderId)
[调用接口] LoadFolderPermission(token=tok, folderId=fid) → permResp
[If] permResp.result != 0 → 「目录查询失败」【End】
[ForEach] p ∈ permResp.data.permissions
    └─ [If] memberId==idInt && memberType==1 && entryId==folderId → already=true; curCate=p.permCateId
[If] already && curCate==permCateId → 「已授权，跳过」【End】
[If] already && curCate!=permCateId → 【调用接口】NewSetFolderPermission(changePermissions) → 返回
[否则] → 【调用接口】NewSetFolderPermission(newPermissions) → 返回
```

## 六、接口③ `removePersonPermission`（修复版 · 先查后删）

### 📦 前置：新建结构体 `app::structures::HyPermHit`

「先查后删」两阶段之间要暂存"命中项"，`hitList` 是 `List<HyPermHit>`，故先建这个结构体：

| 字段名（必须完全照抄） | 类型（CodeWave 选） | 非空 | 说明 |
|---|---|---|---|
| `folderId` | **String**（字符串） | ✅ 勾 | 命中的目录 id，从单列 SQL 的 `folderItem` **原样存字符串**，删除时再 `Convert<Integer>` |
| `permCateId` | **Integer**（整数） | ✅ 勾 | 查出来的**真实**权限类别（8 / 9 / 12），替代旧版写死的 9 |
| `permType` | **Integer**（整数） | ✅ 勾 | 查出来的 permType（一般 10），避免序列化 null → 鸿翼 400 |

> 建法：资源树 →「结构体」→ 新建 `HyPermHit` → 归属 `app::structures` → 加上述 3 字段。
> 🔴 字段名必须与上表**逐字一致**（NASL 里 `app::structures::HyPermHit { folderId = …, permCateId = …, permType = … }` 按名字匹配）。
> 🔴 `folderId` 一定要是 **String**，不要图省事建 Integer —— `permissions[].entryId` 是 string，比较时必须同为 string。

### 6.1 与旧版的逐段 diff

| 段 | 旧版 | 新版 |
|---|---|---|
| 取 token | 头部 1 次 + **循环内每轮 1 次** | **头部 1 次**，`tok` 全局透传 |
| 待删来源 | 直接用 `level IN (1,2)` 的全部目录 | **先查**出 direct 命中的目录，**再删** |
| 无权限时 | 照样发 N 次删除请求 | **直接返回"无直接授权，无需移除"** |
| 删除参数 | `permCateId` 写死 9 | **带查出来的真实 `permCateId` / `permType`** |
| 失败处理 | 一轮失败 `end` 整体中止 | **累计失败清单**，跑完统一返回 |
| 范围 | 仅 L1/L2（漏 L4） | `scope` 参数：`resident`(L1/L2) / `all`(含 L3/L4) |

### 6.2 NASL 参考（完整）

```nasl
using nasl::core;
using nasl::collection;
using nasl::util;

@(description = '移除某人在鸿翼目录的权限：先查 direct 命中 → 只删命中项 → 复扫（开放为接口）')
logic removePersonPermission(employeeId: String, scope: String = 'resident') => result: String {
    let tok;                                   /* ★ 全程一份 token */
    let identityId: List<Integer>;
    let idInt: Integer;
    let scanFolders;
    let folderItem: String;
    let permResp;
    let permList;
    let hitList: List<app::structures::HyPermHit> = []: List<app::structures::HyPermHit>;
    let h: app::structures::HyPermHit;
    let delItem: apis::jyglyc::structures::mermbers;
    let delList: List<apis::jyglyc::structures::mermbers> = []: List<apis::jyglyc::structures::mermbers>;
    let apiResult;
    let okCount: Integer = 0;
    let failMsg: String = '';

    /* ① 取 token + 解析人员 */
    tok = app::logics::hyGetToken(undefined);
    identityId = app::logics::getIdentityIdByAccount(tok, employeeId);
    if ((!HasValue(identityId)) || (Get(identityId, 0) <= 0)) {
        result = s"解析人员失败:${employeeId}";
        end;
    } else {
    }
    idInt = Get(identityId, 0);

    /* ② 待扫目录 */
    if (scope == 'all') {
        scanFolders = sql"SELECT folderId FROM JyglHyFolderMap WHERE isDelete = 0 AND level IN (1,2,3,4)";
    } else {
        scanFolders = sql"SELECT folderId FROM JyglHyFolderMap WHERE isDelete = 0 AND level IN (1,2)";
    }
    if ((!HasValue(scanFolders)) || (Length(scanFolders) <= 0)) {
        result = '目录映射表无数据';
        end;
    } else {
    }

    /* ③ 先查：收集 direct 命中项（★ 本接口的核心修复点） */
    for (folderItem in scanFolders, index in 0) {
        permResp = apis::jyglqxcx::interfaces::s<LoadFolderPermission接口id>(
            token = tok,
            folderId = Convert<Integer>(folderItem),
        );
        if (permResp.result == 0) {
            permList = permResp.data.permissions;
            if ((HasValue(permList)) && (Length(permList) > 0)) {
                for (p in permList, i in 0) {
                    /* 本人 + 个人 + entryId==本目录 ⇒ direct，可删；继承项跳过 */
                    if (((p.memberId == idInt) && (p.memberType == 1)) && (p.entryId == folderItem)) {
                        Add(hitList, app::structures::HyPermHit {
                            folderId = folderItem,
                            permCateId = p.permCateId,
                            permType = p.permType,
                        });
                    } else {
                    }
                }
            } else {
            }
        } else {
            /* 单目录查询失败（801 等）静默跳过，不影响整体 */
        }
    }

    /* ④ 无 direct 命中 ⇒ 直接返回，一次删除请求都不发 */
    if ((!HasValue(hitList)) || (Length(hitList) <= 0)) {
        result = s"该人无直接授权，无需移除：${employeeId}（已扫 ${Length(scanFolders)} 个目录）";
        end;
    } else {
    }

    /* ⑤ 只删命中项，逐条精确删（带真实 permCateId/permType） */
    for (h in hitList, i in 0) {
        Clear(delList, 'deep');
        {
            delItem.memberId = idInt;
            delItem.memberType = 1;
            delItem.permCateId = h.permCateId;     /* ★ 用查出来的真实类别，不再写死 9 */
            delItem.permType = h.permType;         /* ★ 同上；若查出来是空，兜底 10 */
        };
        Add(delList, delItem);
        apiResult = apis::jyglyc::interfaces::s880b67f940e516976cf31b54c1391675(
            Content_Type = undefined,
            Body = apis::jyglyc::structures::S880b67f940e516976cf31b54c1391675Body {
                token = tok,
                folderId = Convert<Integer>(h.folderId),
                mermbers = delList,
            },
        );
        if (apiResult.result == 0) {
            okCount = okCount + 1;
        } else {
            failMsg = s"${failMsg}[目录${h.folderId} 码${apiResult.result}]";
        }
    }

    /* ⑥ 汇总 */
    if (Length(failMsg) > 0) {
        result = s"部分失败：命中 ${Length(hitList)} 个，成功 ${okCount} 个，失败 ${failMsg}";
    } else {
        result = s"移除成功：${employeeId}，共清除 ${okCount} 条直接授权";
    }
    end;
}
```

> 💡 **`permType` 兜底**：若某条 `permissions` 里 `permType` 为空，`delItem.permType` 会被序列化成 null → 鸿翼 400。
> 稳妥写法：`if (HasValue(h.permType)) { delItem.permType = h.permType; } else { delItem.permType = 10; }`
> —— 若 `HyPermHit.permType` 声明为 `Integer`（非空类型），则默认就有值，无需兜底。

> 💡 **`scope` 是可选项，不想要就删**（19:55 主人追问后明确）：本参数**不是修漏洞的必需项** —— 修漏洞只需「token 提循环外 + 先查后删 + 用真实 permCateId/permType + 失败不中断」，这几条与 `scope` 无关。它只为"顺带能扫 L3/L4"存在，而逐课 L4 全扫会超时（§八），另有附录 A 定向清更优。
> **删法（2 处）**：① 签名改回 `removePersonPermission(employeeId: String) => result: String`；② 把 `if (scope == 'all') {…} else {…}` 两分支合并成一行固定 `scanFolders = sql"SELECT folderId FROM JyglHyFolderMap WHERE isDelete = 0 AND level IN (1,2)";`。**其余一字不动。**

## 八、扫描范围：一个必须知道的性能真相

| scope | 覆盖层级 | 目录条数（量级） | 一次查询接口耗时（串行） |
|---|---|---|---|
| `resident`（默认） | L1 应用 + L2 学院 | **约 10~20** | **秒级** ✅ |
| `all` | 再加 L3 学年 + L4 课程 | **可能上百** | **1~4 分钟** ⚠️ 有超时风险 |

> 数据来源：skill 实测 `LoadFolderPermission` 暴力扫 1..1500（16 线程）约 30s ⇒ 单次约 0.3s；串行 N 次 ≈ 0.3N 秒。
> 🔴 **开放为 HTTP 接口后，`all` 很可能被网关/平台超时打断**。

### 所以：逐课 L4 权限不要靠全扫来清

项目真正的授权主体是**课程 L4**（09-09 定论），数量大。正确做法是**定向清**：
已知 `groupId` → 查它对应的 L4 `folderId`（`JyglHyFolderMap WHERE level=4 AND pathKey LIKE '%|学年-学期|课程号'`）→ 只查 1 个目录、只删 1 条。
1 次查询 + 1 次删除，**毫秒级**。完整逻辑见附录 A。

## 九、踩坑清单

1. 🔴 **循环内只能「调用接口」，不能「调用逻辑」**（CodeWave C18/C40）。所以 `grantFolderPermission`、`getIdentityIdByAccount`、`deleteFolderPermission` 这类**服务端逻辑都不能出现在循环体里**——本方案已把 `hyGetToken`/`getIdentityIdByAccount` 全部提到循环外，循环体里只有 `LoadFolderPermission` / `DeleteFolderPermission` 两个**接口**调用。
2. 🔴 **token 循环内重复取 = 自杀**。`hyGetToken` 每次真登录，鸿翼「同账号再登立刻作废前一份」⇒ 必须**头部取一次、透传到底**。
3. 🔴 **`permType` 必须显式赋 10**，否则序列化 null → 鸿翼 400。
4. 🔴 **`folderId` 列是 VARCHAR(64)**，传接口前必须 `Convert<Integer>`。
5. ⚠️ **SQL 多列/自定义列可能返"幻影类型 53724c75"而崩** → 一律 `SELECT *`，字段用实体属性驼峰（`v.pathKey` / `v.level` / `v.folderId`）。单列时 `SELECT folderId` 可（现有代码已验证）。
6. 🔴 **`sql"..."` 里的 `${}` 只能插变量本身**，不能写 `Get(...)`/函数调用。需要取值先赋给变量。
7. 🔴 **Body 数组字段名是 `mermbers`**（鸿翼原始拼写，非 `members`）；`NewSetFolderPermission` 的字段是 **`newPermissions`**（不是 `permissions`）。
8. **删除只对 `entryId == folderId` 的 direct 项**；继承项（`state=1` / `inheritPath` 非空）不删 —— 删了也没用。
9. **单个目录查询/删除失败不要 `end`**（一个 801 坏目录会毁掉整批）；累计失败信息最后统一返回。
10. **开放为接口后必须「发布应用」**才生效（否则 API 管理看不到、外调 404）；改逻辑要重发布 + 调用方同步。
11. **开放接口的入参默认必填** —— `scope` / `permCateId` 要设**默认值**才变可选。
12. **鉴权默认 `akSkAuth`**：header `ak` / `timestamp` / `signature`，`signature = md5(ak+sk+timestamp)`。中文参数注意 URL 编码。
13. 🔴 **`entryId` 官方类型是 `string`（非 integer）** —— 09-10 核对 `swagger.json` 的 `PermissionListModel` 确认。单列 `SELECT folderId` 返回的 `folderItem` 也是 `String` ⇒ 两者**直接比较**（`p.entryId == folderItem`），⛔ **不要写 `Convert<Integer>(p.entryId)`**（会编译错或恒 false）。而 `folderId` 入参是 `integer`，传给接口时**必须** `Convert<Integer>(folderItem)`。一句话：**判相等按 string、传参按 integer**。
14. ⚠️ **同一目录同一人理论上只有一条 direct 记录**；若 `permissions` 出现重复项，`hitList` 会重复 → 第二次删除返回非 0 被记成"失败"。需要严格时可加"同 folderId 去重"再删。
15. ⚠️ **GET 接口要不要传 `Content_Type`？** 语义上**不需要**（GET 无 requestBody，Content-Type 只描述 body 媒体类型）；但 CodeWave 导入后**通常仍会生成一个 `Content_Type` 参数**。证据（09-10 实测 `swagger.json`）：**官方 swagger 里 header 参数共 0 个**，而 `s880b67f940e516976cf31b54c1391675` 的调用写的是 `Content_Type = undefined` ⇒ 该参数是**平台统一生成**的，与 swagger 有没有 header 定义无关。
    ⇒ 结论：**以 IDE 实际提示的签名为准** —— 签名里有就写 `Content_Type = undefined`（GET 传 undefined 无害），没有就删掉。我们生成的导入 JSON 与官方一致（无 header 参数，`LoadFolderPermission` 只有 2 个 query 参数、无 requestBody），故预期签名是 `(token, folderId)`，但多出 `Content_Type` 属正常现象、不算错。
    🔴 **本接口一个自定义请求头都不需要**：没有 body ⇒ 不需要 Content-Type；鉴权走 **query 参数 `token`** ⇒ 不需要 `Authorization` / 自定义头。所以 `Content_Type = undefined` 的语义就是"不发这个头"，正是想要的。
16. 🔴 **可视化拖拽后，循环变量会被平台重命名，引用处必须同步改**（09-10 主人实测踩到）：循环头变成 `for (item in scanFolders, index in 0)` / `for (item1 in permList, index1 in 0)` / `for (Item in hitList, index in 0)`，而**手写的 `folderItem` / `h` 会变成"声明了但从未赋值"的空壳**。
    **症状**：查的时候 `Convert<Integer>(folderItem)` 恒为 0 → 传 folderId=0 ⇒ 801 或查错目录；删的时候删错目录；`item1.entryId == folderItem` 恒 false ⇒ 永远"无直接授权"。
    **自查**：全逻辑搜 `folderItem`，若循环头写的是 `item` 而引用处还是 `folderItem`，就是没改干净。三个引用点：`Convert<Integer>(item)`、`item1.entryId == item`、`Convert<Integer>(Item.folderId)`。
17. 🔴 **列表变量必须初始化**：`let hitList: List<app::structures::HyPermHit>;` ❌ → 必须 `= []: List<app::structures::HyPermHit>;` ✅。未初始化时 `Add` 无效（或运行时报错），导致 ④ 步永远判"无命中"。
18. 🔴 **成功/失败判断别写反**：删除接口 **`result == 0` 才是成功**（`okCount + 1`），非 0 记 `failMsg`。写反的后果是"删成功被记成失败、跑不动"。
19. ⚠️ **`scope: String` 若不加默认值，开放为接口后该参数必填**（CodeWave 开放接口的入参默认必填）。要"只传工号也能跑"就写 `scope: String = 'resident'`。
20. 🔴 **列表判空别用 `Length`（09-10 20:59 主人实测）**：官方「内置函数总览」（`codewave-brain` `03.内置函数使用说明.md` §3）里 **`Length` 属「字符串函数」组**，列表函数组**没有** Length/Count。对 **`List<结构体>`**（`SELECT *` / 多列结果）传参会报**参数类型不一致**；对 String 与单列 `List<String>` 可以（项目里有跑通先例）。
    ⇒ **列表判空一律只写 `HasValue(x)`** —— 官方 `HasValue` 定义：「**null、空字符串、纯空格和长度为 0 的集合**等被视为无效值」⇒ 空列表/空串天然返回 `false`，单判已足够。
    ⇒ 本文档各处 `Length(x) <= 0` / `Length(x) > 0`（`scanFolders` / `hitList` / `permList` / `rows` / `folderRows` 等**列表**）如遇编译报错，**照此退回 `HasValue` 单判**；`Length(failMsg)`、`Length(grantResult)` 是 String，可保留。
    ⚠️ 这会连带波及 `grantResidentL1/L2` 与 `removePersonPermission` 的同类写法，改完务必**保存 + 发布**再验。

## 附录 A · 定向清权（清某课的逐课授权，毫秒级，推荐用于 L4）

> 用途：只清「某人在某门课 L4 目录」上的授权（不改常驻 L1/L2）。
> 相比全扫方案：**无循环、1 查 1 删**，天然规避所有循环红线，也最快。

```nasl
using nasl::core;
using nasl::collection;
using nasl::util;

@(description = '定向移除某人在某课程L4目录的授权（先查后删，无循环；开放为接口）')
logic removePersonPermissionOnCourse(employeeId: String, courseCode: String, academicYear: String, semester: String) => result: String {
    let tok;
    let identityId: List<Integer>;
    let idInt: Integer;
    let folderRows;                        /* SELECT * → 取 folderId */
    let folderId: String = '';
    let permResp;
    let permList;
    let delItem: apis::jyglyc::structures::mermbers;
    let delList: List<apis::jyglyc::structures::mermbers> = []: List<apis::jyglyc::structures::mermbers>;
    let apiResult;
    let hitCate: Integer = 0;
    let hitType: Integer = 10;

    tok = app::logics::hyGetToken(undefined);
    identityId = app::logics::getIdentityIdByAccount(tok, employeeId);
    if ((!HasValue(identityId)) || (Get(identityId, 0) <= 0)) {
        result = s"解析人员失败:${employeeId}";
        end;
    } else {
    }
    idInt = Get(identityId, 0);

    /* 定位该课程的 L4 目录（pathKey 形如 计算机学院|2025-2026-1|J9041002） */
    folderRows = sql"SELECT * FROM JyglHyFolderMap WHERE level = 4 AND isDelete = 0 AND pathKey LIKE ${...}";
    /* ⚠️ LIKE 的拼接串要先算进 String 变量再插：
       let likeKey: String = s"%|${academicYear}-${semester}|${courseCode}";
       folderRows = sql"SELECT * FROM JyglHyFolderMap WHERE level = 4 AND isDelete = 0 AND pathKey LIKE ${likeKey} LIMIT 1"; */
    if ((!HasValue(folderRows)) || (Length(folderRows) <= 0)) {
        result = s"未找到课程L4目录：${courseCode}";
        end;
    } else {
    }
    folderId = Get(folderRows, 0).folderId;

    /* 先查：该人在这条目录上有没有 direct 授权 */
    permResp = apis::jyglqxcx::interfaces::s<LoadFolderPermission接口id>(
        token = tok,
        folderId = Convert<Integer>(folderId),
    );
    if (permResp.result != 0) {
        result = s"查询失败：码 ${permResp.result}";
        end;
    } else {
    }
    permList = permResp.data.permissions;
    if ((HasValue(permList)) && (Length(permList) > 0)) {
        for (p in permList, i in 0) {
            if (((p.memberId == idInt) && (p.memberType == 1)) && (p.entryId == folderId)) {
                hitCate = p.permCateId;
                hitType = p.permType;
            } else {
            }
        }
    } else {
    }
    if (hitCate <= 0) {
        result = s"该人在此课程无直接授权，无需移除：${employeeId} @ ${folderId}";
        end;
    } else {
    }

    /* 删除 */
    Clear(delList, 'deep');
    {
        delItem.memberId = idInt;
        delItem.memberType = 1;
        delItem.permCateId = hitCate;
        delItem.permType = hitType;
    };
    Add(delList, delItem);
    apiResult = apis::jyglyc::interfaces::s880b67f940e516976cf31b54c1391675(
        Content_Type = undefined,
        Body = apis::jyglyc::structures::S880b67f940e516976cf31b54c1391675Body {
            token = tok,
            folderId = Convert<Integer>(folderId),
            mermbers = delList,
        },
    );
    if (apiResult.result == 0) {
        result = s"移除成功：${employeeId} @ 课程${courseCode}（目录${folderId}）";
    } else {
        result = s"移除失败：码 ${apiResult.result}";
    }
    end;
}
```
