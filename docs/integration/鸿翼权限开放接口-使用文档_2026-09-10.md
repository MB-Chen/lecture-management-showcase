## 〇、四个接口解决什么

四个接口构成「**查 → 授 → 回收**」的闭环：

| 场景 | 调哪个接口 |
|---|---|
| **这个人现在有什么权限？**（核对 / 清权前预检） | `getPersonPermissions` |
| 给**教务处处长**授常驻权限（讲义管理根 L1，全校唯一） | `grantResidentL1` |
| 给**教学院长 / 教学秘书**授常驻权限（本学院 L2） | `grantResidentL2` |
| 人员**换岗 / 离职 / 误授**，回收权限 | `removePersonPermission` |

| | `getPersonPermissions` | `grantResidentL1` | `grantResidentL2` | `removePersonPermission` |
|---|---|---|---|---|
| 作用 | **查**某人的直接授权 | 授 L1（讲义管理根） | 授 L2（本学院） | 移除直接授权 |
| 必填入参 | `employeeId` | `employeeId`, `roleName` | `employeeId`, `roleName` | `employeeId` |
| 可选入参 | `scope`（默认 `resident`） | — | — | `scope`（默认 `resident`） |
| `roleName` 取值 | — | `教务处处长` | `教学院长` / `教学秘书` | — |
| 授权层级 | L1/L2（或含 L3/L4） | `level=1` | `level=2 AND pathKey=学院名` | L1/L2（或含 L3/L4） |
| 典型耗时 | 默认秒级 / `all` 分钟级 | 秒级 | 秒级 | 默认秒级 / `all` 可能分钟级 |
| 返回格式 | 🔴 **JSON** | 中文文案 | 中文文案 | 中文文案 |
| 成功判据 | `code == 0` | `授权成功：` | `授权成功：` | `移除成功：` / `该人无直接授权` |

> 💡 **编排顺序**：换岗先 `getPersonPermissions` 看现状 → `removePersonPermission` 清旧 → 再 `grantResidentL1/L2` 授新 → 最后再查一次验收。
> ⛔ **不要反向**（先授后清会把自己刚授的清掉）。

## 一、通用调用约定（四个接口一样）

### 1.1 调用地址

```
{制品域名}/rest/getPersonPermissions
{制品域名}/rest/grantResidentL1
{制品域名}/rest/grantResidentL2
{制品域名}/rest/removePersonPermission
```

- `{制品域名}` = **本 CodeWave 应用自己的制品域名**（⛔ **不是鸿翼的 IP/域名**）。
  位置：**集成中心 → 应用API管理 → 找到本应用分组**，可看到实际域名与接口定义。
- 请求路径默认 `/rest/{逻辑名}`；若开放接口时改过路径，以 API 管理页实际显示为准（官方规则：外部调用地址 = **制品应用域名 + 接口请求路径**）。

### 1.2 鉴权（akSkAuth，放 HTTP Header）

| Header | 含义 | 说明 |
|---|---|---|
| `ak` | Access Key | 相当于用户名，由接口提供方分配 |
| `timestamp` | 时间戳 | 当前 **Unix 秒**（10 位），防重放 |
| `signature` | 签名 | `md5(ak + sk + timestamp)`，**32 位小写十六进制** |

- `sk`（Secret Key）**不在请求中传递**，只在服务端参与签名校验 —— 由接口提供方告知。
- 🔴 **鉴权头缺失或签名错误 → `401`**；通过 → `200`。
- `ak` / `sk` 由本应用开发者在鉴权逻辑中设定，**调用方需向开发者索取**。

### 1.3 参数与返回

| 项 | 约定 |
|---|---|
| 请求方式 | 逻辑入参**默认映射为 URL Query**（`GET` + `?employeeId=…`）⚠️ 以 API 管理页 / 导出的 swagger 定义为准 |
| 必填性 | 开放接口入参**默认必填**；**只有设了默认值的参数才可选**（本组仅 `scope` 有默认值） |
| 中文参数 | 🔴 **必须 URL 编码**，否则服务端收到乱码 → 角色校验必然失败（curl 用 `--data-urlencode`） |
| 成功返回 | `HTTP 200`，响应体 = 逻辑输出 `result` |
| 返回格式 | `getPersonPermissions` = **JSON 字符串**；其余三个 = **纯中文文案**（详见 §六） |
| 失败返回 | 鉴权失败 `401`；逻辑内的业务失败**仍是 `200`**，靠**内容**（JSON 的 `code` / 文案前缀）判断 |

### 1.4 四条通用规则

1. 🔴 **改完逻辑必须「发布应用」**，否则外部调用 404；接口更新后**调用方需同步接口**（CodeWave 应用内调用需在问题栏提示或走「更新接口」）。
2. 🔴 **换岗 / 离职务必调 `removePersonPermission`**——`grantResidentL1/L2` **只授不撤**，旧权限不会自动消失。
3. ✅ **重复调用安全**：授权幂等；清权在无命中时**一个删除请求都不发**（鸿翼侧零操作记录）；查询**纯只读**，随便调。
4. 🔴 **`employeeId` 一律是工号**（如 `41255`），不是鸿翼 `identityId`、也不是姓名。需求文档里写的 `userId` = `employee_id` = `currentUser.userId`，**同一个东西**；接口内部自动转 `identityId`，调用方不需要关心。

## 二、接口 ①：`getPersonPermissions` —— 查某人有什么权限

| 项 | 内容 |
|---|---|
| 用途 | 查某工号在鸿翼目录上的**直接授权**清单（核对用 / 清权前预检） |
| 方法 / 路径 | `GET {制品域名}/rest/getPersonPermissions` |
| 核心行为 | 逐个目录调鸿翼 `LoadFolderPermission`，只收「**本人 + 个人授权 + 直接授权**」的命中项 |
| 只读 | ✅ **纯查询，零副作用**，可放心反复调用 |
| 🔴 返回格式 | **JSON 字符串**（与另外三个接口的中文文案不同） |

**入参**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `employeeId` | String | ✅ | 被查询人**工号** |
| `scope` | String | ❌ **可选** | **有默认值 `resident`，不传即按默认**。<br>`resident`（默认）= 扫 **L1 应用 + L2 学院**（常驻授权范围），约 10~20 个目录，**秒级** ✅<br>`all` = 再含 **L3 学年 + L4 课程**（逐课授权在这），可能上百个目录，**1~4 分钟，有超时风险** ⚠️ |

**返回 JSON**

```json
{"code":0,"employeeId":"41255","identityId":1208,"scope":"resident","count":2,
 "permissions":[{"folderId":"161","pathKey":"讲义管理","permCateId":9,"permType":10},
                {"folderId":"174","pathKey":"计算机学院","permCateId":9,"permType":10}]}
```

| 字段 | 说明 |
|---|---|
| `code` | **0 = 查询成功**；`1` = 参数错误 / 解析人员失败；`2` = 目录映射表无数据 |
| `employeeId` / `identityId` | 工号 / 转换后的鸿翼人员 id（排查用） |
| `scope` | 实际扫描范围 |
| `count` | 命中条数 |
| `permissions[].folderId` | 目录 id |
| `permissions[].pathKey` | **目录路径名**（如 `计算机学院\|2025-2026-1\|J9041002`），管理端直接显示这个 |
| `permissions[].permCateId` | 权限类别：**7 无 / 16 显示 / 8 仅预览 / 9 预览+下载 / 17 上传新建 / 10 编辑 / 18 子级管理 / 12 管理** |
| `permissions[].permType` | 10 = 分配权限 / 20 = 流程权限 |

**返回码表**

| 情况 | 返回 |
|---|---|
| ✅ 查到 N 条 | `code:0`，`count:N` |
| ✅ **这人一条都没有** | `code:0`，`count:0`，`permissions:[]` —— 🔴 **这是正常结果，不是错误** |
| ❌ 参数为空 | `code:1`，`msg:"参数错误：employeeId 为空"` |
| ❌ 工号解析失败 | `code:1`，`msg:"解析人员失败:{工号}"` |
| ❌ 目录表无数据 | `code:2`，`msg:"目录映射表无数据"` |

**调用示例**

```bash
TS=$(date +%s)
SIG=$(printf "%s" "${AK}${SK}${TS}" | md5sum | cut -d' ' -f1)

# 只传工号（默认 scope=resident，秒级）
curl -G "{制品域名}/rest/getPersonPermissions" \
  -H "ak: ${AK}" -H "timestamp: ${TS}" -H "signature: ${SIG}" \
  --data-urlencode "employeeId=41255"

# 连逐课 L4 一起查（慢，慎用）
curl -G "{制品域名}/rest/getPersonPermissions" \
  -H "ak: ${AK}" -H "timestamp: ${TS}" -H "signature: ${SIG}" \
  --data-urlencode "employeeId=41255" \
  --data-urlencode "scope=all"
```

**⚠️ 调用方必读**

- 🔴 **只报「直接授权」** —— 从上级目录**继承**来的权限**不报**（例如院长授了 L2、靠继承能看 L3/L4，查 L3/L4 时 `count=0` 是**正确**的）。
  ⇒ 想看"这人实际能看什么"，请查**上层目录**（L1 / L2）的权限项，或用 `scope=resident`。
- 🔴 `code:0` + `count:0` **不是故障**。要区分「查失败」和「这人没权限」，只看 `code`。
- `scope=all` 在生产环境慎用（可能超时）。查逐课 L4 建议走**定向**接口（另行索取）。

## 三、接口 ②：`grantResidentL1` —— 授「教务处处长」讲义管理根权限

| 项 | 内容 |
|---|---|
| 用途 | 给指定工号授 **L1 讲义管理根**（全校唯一，`level=1`）的常驻权限 |
| 方法 / 路径 | `GET {制品域名}/rest/grantResidentL1` |
| 授权内容 | `memberType=1`（个人）、`permCateId=9`（预览+下载），**只授不撤** |

**入参**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `employeeId` | String | ✅ | 被授权人**工号**（如 `41255`） |
| `roleName` | String | ✅ | 角色中文名，此处**必须为** `教务处处长`（精确匹配，不能写 `DIRECTOR`） |

| 情况 | 文案 |
|---|---|
| ✅ 成功 | `授权成功：{工号} → L1 讲义管理根` |

**调用示例**

## 四、接口 ③：`grantResidentL2` —— 授「教学院长 / 教学秘书」本学院权限

| 🔴 学院来源 | **接口内部用工号自动查**（教务库 `SysTeacherInfo` → `SysDepartmentInformation`），**调用方不要传学院名** |

**入参**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `employeeId` | String | ✅ | 被授权人**工号** |
| `roleName` | String | ✅ | `教学院长` 或 `教学秘书`（精确匹配，不能写 `DEAN` / `SECRETARY`） |

**返回文案**（`result : String`）

**调用示例**

```bash
TS=$(date +%s)

curl -G "{制品域名}/rest/grantResidentL2" \
```

**⚠️ 调用方必读**

- **跨学院的人只会授到「查出来的第一个学院」**。某人若兼顾多个学院，**需按学院分别确认**（本接口一次只处理一个学院，内部不做多学院循环）。
- 学院名**来自教务库**，不是入参。若该学院在教务库无记录、或名称与讲义库 `pathKey` **口径不一致**，会返回「未找到学院L2目录」——需人工核对两库学院名。

## 五、接口 ④：`removePersonPermission` —— 移除某人的权限

| 项 | 内容 |
|---|---|
| 用途 | 移除某人在鸿翼目录上的**直接授权**（个人授权） |
| 方法 / 路径 | `GET {制品域名}/rest/removePersonPermission` |
| 核心行为 | 🔴 **先查后删**：先逐个目录查该人是否有**直接授权**，**只删命中的**；若无命中 → **一个删除请求都不发**，直接返回 |
| 继承权限 | 从上级目录继承来的权限**不删、也删不动**——删掉直接授权那处，继承自然消失 |

**入参**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `employeeId` | String | ✅ | 要清权的**工号** |
| `scope` | String | ❌ **可选** | **有默认值 `resident`，不传即按默认**。<br>`resident`（默认）= 扫 **L1 应用 + L2 学院**，约 10~20 个目录，**秒级** ✅<br>`all` = 再含 **L3 学年 + L4 课程**，可能上百个目录，**1~4 分钟，有超时风险** ⚠️ |

> 💡 **逐课 L4 权限不要用 `scope=all` 全扫**（慢、可能被网关超时打断）。本项目另有**定向清某门课**的接口 `removePersonPermissionOnCourse`（毫秒级），需要时另行索取。

**返回文案**

| 情况 | 文案 | 调用方怎么理解 |
|---|---|---|
| ✅ 有权限、全删成功 | `移除成功：{工号}，共清除 N 条直接授权` | 成功，N ≥ 1 |
| ⚠️ 部分失败 | `部分失败：命中 N 个，成功 M 个，失败 [目录{id}码{code}]…` | 有目录删失败，**需人工跟进** |
| ✅ 本来就没权限 | `该人无直接授权，无需移除：{工号}（已扫 N 个目录）` | **正常结果，不是错误**（鸿翼侧零操作记录） |
| ❌ 工号解析失败 | `解析人员失败:{工号}` | 工号在鸿翼找不到对应人员 |
| ❌ 目录表无数据 | `目录映射表无数据` | 环境异常，联系管理员 |

**调用示例**

```bash
TS=$(date +%s)
SIG=$(printf "%s" "${AK}${SK}${TS}" | md5sum | cut -d' ' -f1)

# 清常驻权限（L1 + L2，默认，秒级）
curl -G "{制品域名}/rest/removePersonPermission" \
  -H "ak: ${AK}" -H "timestamp: ${TS}" -H "signature: ${SIG}" \
  --data-urlencode "employeeId=41255"

# 连逐课 L4 一起清（慢，慎用）
curl -G "{制品域名}/rest/removePersonPermission" \
  -H "ak: ${AK}" -H "timestamp: ${TS}" -H "signature: ${SIG}" \
  --data-urlencode "employeeId=41255" \
  --data-urlencode "scope=all"
```

**⚠️ 使用提醒**

- 这是**破坏性操作**，建议管理端做**二次确认**（显示被清权人姓名 + 工号）。
- ✅ **清权前建议先调 `getPersonPermissions`**（接口 ①）核对一遍，把 `pathKey` 显示给用户确认。
- 清权**不区分权限来源**：无论是处长/院长手工授的还是审批流程自动授的，只要是该人的**直接授权**都会清掉。

## 六、结果判断（🔴 对接关键）

**接口 ① 返回 JSON，接口 ②③④ 返回中文文案** —— 判读方式不同，别混用。

### 6.1 接口 ① `getPersonPermissions`：解析 JSON


### 6.2 接口 ②③④：按文案前缀匹配

| 接口 | 判成功的文案前缀 | 需要告警的 |
|---|---|---|
| `grantResidentL1` | `授权成功：` | 其余全部 |
| `grantResidentL2` | `授权成功：` | 其余全部 |

- ⚠️ HTTP `200` 只说明**鉴权通过、逻辑跑完了**，业务成败**看内容**。

## 七、常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 返回 **401** | 鉴权头缺失 / `signature` 算错 / `timestamp` 过期 | 检查 `signature = md5(ak+sk+timestamp)`（32 位小写）；重新取当前时间戳 |
| 外部调 **404** | 逻辑没开放为接口，或**改完没发布应用** | 重新「开放为接口」+ **发布应用** |
| 参数传了却收不到 / 报参数缺失 | 请求方式或参数位置不对 | 到 API 管理页看接口定义（query / body / form），按其定义传 |
| 中文 `roleName` 校验失败 | 中文**未 URL 编码**，服务端收到乱码 | 用 `--data-urlencode`（curl）或 `encodeURIComponent`（JS） |
| 返回「角色不符」 | 入参是**英文枚举**（`DIRECTOR`/`DEAN`/`SECRETARY`），本接口只认**中文** | 调用方先映射成中文：`教务处处长` / `教学院长` / `教学秘书` |
| 返回「解析人员失败」 | 工号在鸿翼无对应人员（人员未同步） | 核对工号；确认该人已在鸿翼组织架构中 |
| 返回「未查到该工号所属学院」 | 教务库无该工号的学院记录 | 核对教务库人员与学院数据 |
| 返回「未找到学院L2目录」 | 讲义库 `pathKey` 与教务库学院名**不一致**（或该学院目录未建） | 人工核对两库学院名口径 |
| 返回「未找到L1讲义管理根目录」 | 讲义库目录映射缺失 | 联系管理员检查 `JyglHyFolderMap` |
| 返回「部分失败」 | 个别目录删除返回非 0（多为目录状态异常） | 按文案里 `[目录xxx码y]` 到鸿翼后台核对 |
| 🔴 查询接口**永远 `count:0`**，但鸿翼后台明明有授权 | ① 权限是**继承**来的（本接口不报，符合预期）<br>② `scope=resident` 但权限在 L4 → 改 `scope=all`<br>③ 实现类问题：循环变量名没同步 / `hitList` 未初始化 | 依次排查；实现侧自查见 `docs/鸿翼权限查询接口-getPersonPermissions-开放实现_2026-09-11.md` §五 |
| `scope=all` 超时 | 目录上百个、串行查询太慢 | 改用默认 `resident`；逐课清理走定向接口 |

🔴 **拖完必查 9 条**（前两条是"永远 `count:0`"的头号原因）：

| # | 必查项 | 症状 |
|---|---|---|
| 1 | **循环变量名三处引用必须同名** —— `Convert<Integer>(…)`、`….entryId == …`、`….folderId` 要跟循环头一致（平台常把循环头重命名成 `item` / `item1` / `Item`） | 传 `folderId=0` 报 **801**，或比较**恒 false** ⇒ 永远 `count:0` |
| 2 | **`hitList` 必须初始化 `= []`**，类型 `List<app::structures::HyPermHit>` | `Add` 无效 ⇒ 永远 `count:0` |
| 3 | **判相等按 string、传参按 integer** —— `entryId` / `folderId` 是 String 直接比；接口入参 `folderId` 必须 `Convert<Integer>` | 类型不一致 / 比不中 |
| 4 | **判空只用 `HasValue`** —— `Length` 是字符串函数，对 `List<结构体>` 传参报「参数类型不一致」 | 编译不过 |
| 5 | **循环内只「调用接口」，不「调用逻辑」** ⇒ `hyGetToken` / `getIdentityIdByAccount` 必须放在循环**外**；`hyGetToken` 要传 `undefined` | 编译/运行报错 |
| 6 | **`if` 的"否"分支留空即可**（无 else 也合法），⛔ 不要填 `x = x` 自赋值 | 能编译但平台拖不出来 = 交付物不可用 |
| 7 | **JSON 拼接只能走一条路** —— 方案 B（纯 `s"…"`，双引号用变量 `${q}` 代替）**或** 方案 A（`'…'` 片段 + `+`），⛔ **不能混在同一条表达式** | 🔴 **编译不过**（混用是 3 版拖出代码失败的根因） |
| 8 | 🔴 **`sep` 必须"两处配合"** —— 声明 `let sep: String = '';`（**空串**，不是 `','`）+ 循环体**末尾** `sep = ',';` | 初值给 `','` ⇒ 首条前多逗号 `[,…`；末尾漏写 ⇒ 多条粘成 `}{` ⇒ **JSON 非法**。⚠️ 前者只有 `count=0` 时看不出、后者只有 **1 条命中**时看不出 |
| 9 | 🔴 **JSON 对象的首尾 `{` `}` 都不能漏，且数值不加引号** —— 开头 `{` 写在 `${json}${sep}` **之后**、末尾 `}` 写在该条**最后**（**循环内各只写一次**）；裸 `{` / `}` **直接写即可**（平台接受；仅当报错才改用 `let lb: String = '{'` / `let b: String = '}'` 的 `${lb}` / `${b}`）；`permCateId` / `permType` / `identityId` 的插值**别包** `${q}` | 漏开头 `{` ⇒ 产出 `["folderId":"3",…]`（数组里跟冒号）；漏末尾 `}` ⇒ 对象没闭合；**两种都是 JSON 非法** —— 且只有把产物拉出来看才发现。包了 `${q}` ⇒ 值变字符串、与契约 **integer** 不符，对接方强类型解析失败。另外自增计数器给初值（`hitCount = 0`，否则首次是 `null + 1`） |
