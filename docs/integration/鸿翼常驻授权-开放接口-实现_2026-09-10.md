# 鸿翼「常驻授权」服务端逻辑 + 开放为接口 实现（2026-09-10）

> 需求：新增**两个**后端逻辑——给指定工号授**常驻**鸿翼目录权限（处长→L1 讲义管理根 / 院长·教秘→本学院 L2），
> 并**开放为 HTTP 接口**供外部调用。参照 09-07 已跑通的「清权接口」`removePersonPermission` 同款模式。
>
> ⚠️ CodeWave 逻辑只能拖组件，下文 NASL 仅作**逻辑等价参考**，不能直接粘贴；真正落地看第六、七节操作清单。

### 1.1 两个逻辑的职责与校验规则

| 逻辑 | 入参 | 角色校验（中文→英文） | 授权目标 | 学院要求 |
|---|---|---|---|---|
| `grantResidentL1` | `employeeId`, `roleName` | `roleName == '教务处处长'`（→ DIRECTOR），否则**拒绝** | `level=1`（讲义管理根，全校唯一） | ❌ 不需要 |
| `grantResidentL2` | `employeeId`, `roleName` | `roleName ∈ {教学院长, 教学秘书}`（→ DEAN/SECRETARY），否则**拒绝** | `level=2 AND pathKey=该工号所属学院名` | ✅ 必须查到，查不到→失败 |

> 📌 **为什么拆两个逻辑而不是一个**：职责单一（各自只做一件事），且调用方语义清晰——授处长调 L1 接口、授院长/教秘调 L2 接口。角色不匹配时逻辑内直接返回失败，防止误用。

### 2.3 红线

1. 🔴 **禁用旧 `SetFolderPermission`**（字符串全量替换，会误删他人），只用按成员操作的接口。

5. 🔴 **开放为接口后必须发布应用**才生效，否则外调 404。

## 四、NASL 参考（逻辑等价，实际拖组件）

### 4.1 grantResidentL1（授讲义管理根）

> 📌 代码里 `★1`~`★5` = **L1 的逐点改法编号**（仅本节内有效；两个共同修改点另见 §4.3 的 `A1`~`A3`）。

```nasl
using nasl::core;
using nasl::collection;
using nasl::util;

@(description = '给指定工号授鸿翼L1讲义管理根的常驻权限（仅教务处处长，开放为接口）')   /* ★2 文案补全 + 确认结尾 ')' 闭合 */
logic grantResidentL1(employeeId: String, roleName: String) => result: String {        /* ★1 出参补 : String */
    let tok;                            /* 全程唯一一份 token */
    let identityId: List<Integer>;      /* getIdentityIdByAccount 返回，取 [0] = 鸿翼 identityId */
    let l1FolderId: List<String>;       /* 查到的 L1 目录 folderId（库里是 VARCHAR） */
    let grantResult;                    /* grantFolderPermission 返回：成功='授权成功'，失败=空串 */

    /* ① 角色强校验：只认"教务处处长"（中文入参 → 英文枚举 DIRECTOR） */
    if (roleName != '教务处处长') {
        result = s"角色不符：授L1仅限教务处处长，当前传入 ${roleName}";
        end;
    }

    /* ★3 工号非空校验（新增；🔴 判空一律 HasValue + Length 双判 —— HasValue('') 为真） */
    if ((!HasValue(employeeId)) || (Length(employeeId) <= 0)) {
        result = '参数错误：employeeId 为空';
        end;
    }

    /* ★4 取 token —— 放在角色/参数校验之后：① 只取一次；② 校验不过就不白登一次鸿翼 */
    tok = app::logics::hyGetToken(undefined);

    /* ② 工号 → 鸿翼 identityId */
    identityId = app::logics::getIdentityIdByAccount(tok, employeeId);
    if ((!HasValue(identityId)) || (Get(identityId, 0) <= 0)) {
        result = s"解析人员失败:${employeeId}";
        end;
    }

    /* ③ 定位 L1 讲义管理根（level=1，全校唯一一条） */
    l1FolderId = sql"SELECT folderId FROM JyglHyFolderMap WHERE level = 1 AND isDelete = 0 LIMIT 1";
    if ((!HasValue(l1FolderId)) || (Length(l1FolderId) <= 0)) {
        result = '未找到L1讲义管理根目录';
        end;
    }

    /* ④ 授权：memberType=1(个人) + permCateId=9(预览+下载)；只授不撤、不记账本 */
    grantResult = app::logics::grantFolderPermission(
        tok,
        Convert<Integer>(Get(l1FolderId, 0)),   // VARCHAR → Integer
        Get(identityId, 0),
        1,                                       // memberType=1 用户
        9,                                       // permCateId=9 预览+下载
    );

    /* ★5 按返回值判成败（原版无条件写"授权成功" —— 鸿翼失败也报成功，外部无从判断）
       ⚠️ `grantFolderPermission` 成功时 result='授权成功'，失败时**返回空串且不带错误码**
       ⇒ 必须双判：HasValue('') 为真，只判 HasValue 会把空串判成成功 */
    if ((HasValue(grantResult)) && (Length(grantResult) > 0)) {
        result = s"授权成功：${employeeId} → L1 讲义管理根";
    } else {
        result = s"授权失败：${employeeId} → L1 讲义管理根（grantFolderPermission 未返回成功）";
    }
    end;
}
```

> 💡 **关联建议（可选）**：`grantFolderPermission` 现有实现里失败分支是空的（`if (apiResult.result == 0) { result = '授权成功'; } else { }`），
> 导致调用方只知道"没成功"、**看不到鸿翼返回的错误码**。若想排障方便，给它补一行
> `result = s"授权失败：码 ${apiResult.result}"` —— 属于该逻辑自身的改动，不在本接口范围内。

> ⛔ **趁手记一条通杀红线（09-10 20:38 实测踩到）**：**肯定判用 `&&`、否定判用 `||`，互换即恒真/恒假**。
> 因为 `HasValue('')` 为**真**：
> | 写法 | 结果 |
> |---|---|
> | `HasValue(x) && (Length(x) > 0)` ✅ | **正确**：空串→false（判"有值"） |
> | `HasValue(x) \|\| (Length(x) > 0)` ❌ | **恒真**：空串也 true ⇒ **失败全被记成成功** |
> | `(!HasValue(x)) \|\| (Length(x) <= 0)` ✅ | **正确**：空串→true（判"没值"） |
> | `(!HasValue(x)) && (Length(x) > 0)` ❌ | **恒假**：兜底永不触发 |


### 4.2 grantResidentL2（授本学院）

> 📌 代码里 `L2-1`~`L2-3` = **L2 独有的逐点改法**；`L2-1`（工号非空校验）与 L1 的 `★3` 同段，复制时最容易漏。

```nasl
using nasl::core;
using nasl::collection;
using nasl::util;

@(description = '给指定工号授其所属学院L2目录的常驻权限（教学院长/教学秘书，开放为接口）')
logic grantResidentL2(employeeId: String, roleName: String) => result: String {
    let tok;                            // ★ token 只登一次、全程透传
    let identityId: List<Integer>;      // 鸿翼 identityId
    let collegeNameList: List<String>;  // 用工号查出的学院名（★ 单列 SELECT → List<String>，取值 Get(list,0) 直接得字符串）
    let collegeName: String = '';       // ★ 从集合取出的单个学院名（String，供后续 SQL 插值与文案用）
    let l2FolderId: List<String>;       // 查到的 L2 目录 folderId
    let grantResult;

    /* ⓪ 取 token（★ 整个逻辑只此一次；※ 想省一次登录可挪到 ① 角色校验之后，两者等价） */
    tok = app::logics::hyGetToken(undefined);

    /* ① 角色强校验：只认"教学院长"/"教学秘书" */
    if ((roleName != '教学院长') && (roleName != '教学秘书')) {
        result = s"角色不符：授L2仅限教学院长/教学秘书，当前传入 ${roleName}";
        end;
    }

    /* L2-1 工号非空校验（与 L1 同一段，别漏；🔴 HasValue + Length 双判） */
    if ((!HasValue(employeeId)) || (Length(employeeId) <= 0)) {
        result = '参数错误：employeeId 为空';
        end;
    }

    /* ② 工号 → 鸿翼 identityId */
    identityId = app::logics::getIdentityIdByAccount(tok, employeeId);
    if ((!HasValue(identityId)) || (Get(identityId, 0) <= 0)) {
        result = s"解析人员失败:${employeeId}";
        end;
    }

    /* ③ 工号 → 所属学院名
          ★ 本项目 SQL 组件认【实体大驼峰名】：表名 SysTeacherInfo / SysDepartmentInformation、
             字段 t.college / t.departmentId / d.departmentName 均可用（主人实测不报错）。
             （注：另一个应用的同步逻辑用的是物理名 sys_teacher_info/department_id，两者不冲突，
               以本应用实测为准，勿互相套用）
          ★ 本条 SQL 只 SELECT 一列 → 返回 List<String>，取值 Get(collegeNameList, 0) 即得字符串 */
    collegeNameList = sql"SELECT d.departmentName AS collegeName
                          FROM SysTeacherInfo t
                          LEFT JOIN SysDepartmentInformation d ON t.college = d.departmentId
                          WHERE t.employeeId = ${employeeId} LIMIT 1";
    if (((!HasValue(collegeNameList)) || (Length(collegeNameList) <= 0)) || (!HasValue(Get(collegeNameList, 0)))) {
        result = s"未查到该工号所属学院:${employeeId}";
        end;
    }
    /* ★ 关键：先取出 String 再用于 SQL 插值——SQL 组件的 ${} 只能插变量本身，不能写 Get(...) 表达式 */
    collegeName = Get(collegeNameList, 0);
    if ((!HasValue(collegeName)) || (Length(collegeName) <= 0)) {   /* L2-2 否定判 → 用 || ，且必须 Length 双判 */
        result = s"未查到该工号所属学院:${employeeId}";
        end;
    }

    /* ④ 定位 L2 本学院目录（level=2 AND pathKey=学院名）
          ✅ 插的是 String 变量 collegeName 本身（非 Get 表达式） */
    l2FolderId = sql"SELECT folderId FROM JyglHyFolderMap
                     WHERE level = 2 AND isDelete = 0 AND pathKey = ${collegeName} LIMIT 1";
    if ((!HasValue(l2FolderId)) || (Length(l2FolderId) <= 0)) {
        result = s"未找到学院L2目录：${collegeName}";
        end;
    }

    /* ⑤ 授权：memberType=1(个人) + permCateId=9；只授不撤、不记账本 */
    grantResult = app::logics::grantFolderPermission(
        tok,
        Convert<Integer>(Get(l2FolderId, 0)),
        Get(identityId, 0),
        1,
        9,
    );

    /* L2-3 按返回值判成败（原版 `else` 分支是空的 → 失败时 result 从未被赋值、外部只拿到空串）
       ⚠️ 肯定判必须 `&&` —— `HasValue('')` 为真，写成 `||` 会**恒真**、失败全被记成成功 */
    if ((HasValue(grantResult)) && (Length(grantResult) > 0)) {
        result = s"授权成功：${employeeId} → ${collegeName} L2";
    } else {
        result = s"授权失败：${employeeId} → ${collegeName} L2（grantFolderPermission 未返回成功）";
    }
    end;
}
```

> 🔴 **SQL 组件插值铁律（踩坑修正 09-10）**：`sql"..."` 里的 `${xxx}` **只能插「变量本身」**，**不能写函数调用/表达式**。
> - ❌ 错：`pathKey = ${Get(collegeName, 0)}` → **报错**
> - ✅ 对：`pathKey = ${collegeName}`（`collegeName` 是 String 变量）
> - 若变量是 `List<String>`，**必须先 `collegeName = Get(collegeNameList, 0)` 取出来**再用。（若 SQL 查多列则返回 `List<结构体>`，取值要带字段名 `Get(list,0).别名`。）
> - 可视化拖组件时同理：从右侧面板**拖变量**进 SQL，不能手写 `Get(...)`。

> ⚠️ **数据源边界（09-10 澄清，别再叫「跨库 JOIN」）**：
> - 第 ③ 步的 `SysTeacherInfo` ⋈ `SysDepartmentInformation` **两表同在教务库**（`〈教务库〉` @<内网地址·已脱敏>:6001，见 `教务系统表/*.sql` 头部的 Source Schema）→ **一条 LEFT JOIN 就行，不需要拆**，§4.2 就是这么写的。
> - 真正**跨数据源**的是 **③（教务库）↔ ④（讲义库 `JyglHyFolderMap`）**：CodeWave SQL 组件**只能查单数据源**（`docs/讲义管理系统-CodeWave搭建任务书.md` 平台硬约束1：不支持跨数据源 SQL）→ 这两步**必须写成两条 SQL**，本来也是这么做的，**别试图合并成一条**。
> - 📌 **判据是「数据源」不是「库名」**：项目档案记载讲义自建表走 **CodeWave 默认数据源**（应用自动建表，见 `docs/归档/被V5取代/CodeWave页面搭建指南.md`）、教务 10 表走**另配的「教务数据源」**（`任务书` D1）→ **本就是两个数据源**。所以即便两者物理上在同一个 MySQL 实例、甚至同一个库，只要配成两个数据源，**依然不能写进一条 SQL**；**只有"同一数据源"才可合并**。
> - 因此前置只需确认：该应用**配了这两个数据源**（L1 只需讲义库；L2 两个都要）——**与 JOIN 能力无关**。
> - 退路：若教务库数据源确实加不了，L2 改为**调用方传学院名**（方案不变，仅 ③ 换成入参）。
> - 若真要把 ③ 拆两次：中间那个「院编」要用 **String 变量**接（`let collegeId: String`）再插进第二条 SQL 的 `${collegeId}`。

### 4.3 两处共同修改点（09-10 20:26 复核定稿）

> 主人贴出 IDE 拖拽后的实际代码，与本文早期 §4.1/§4.2 有三处差异，**两个逻辑都要改**：

| # | 问题 | 症状 | 改法 |
|---|---|---|---|
| A1 | 🔴 **`hyGetToken` 在同一逻辑里调了 2 次** | 鸿翼「同账号再登**立刻作废前一个 token**」⇒ 多一次真登录、且第一个 token 随时可能被自己顶掉；若后续在 `grantFolderPermission` 前后还有别的鸿翼调用，会莫名 401/`result:4` | **头部取一次** `let tok; tok = app::logics::hyGetToken(undefined);`，后面 `getIdentityIdByAccount(tok, …)` 与 `grantFolderPermission(tok, …)` 全部透传（与 `removePersonPermission` 同款写法） |
| A2 | ⚠️ **出参漏了类型**：`=> result {` | 开放为 HTTP 接口时出参契约不明确 | 补成 **`=> result: String {`**（两逻辑与本文 §3.1 契约一致） |
| A3 | ⚠️ **成功文案写死，未看 `grantResult`** | 授权实际失败也返回"授权成功"，外部无从判断 | 建议按返回判：`grantResult` 若为对象 → `if (grantResult.result == 0) { 成功 } else { 失败 }`；**以 IDE 提示的类型为准**（若 `grantFolderPermission` 返回 String，则直接拼进文案或判 `HasValue`）。⚠️ 若维持现状，请知悉文案仅代表"流程跑完" |

  └─【变量】tok / identityId / teacherRows / deptRows / collegeId(Integer) / collegeName(String) / l2FolderId(List<String>) / grantResult
        ├─【If】roleName != "教学院长" 且 roleName != "教学秘书"
        │     └─ result = "角色不符：..." 【End 返回】
        ├─【If】employeeId 为空（HasValue + Length 双判）
        │     └─ result = "参数错误：employeeId 为空" 【End 返回】
        ├─【调用逻辑】hyGetToken() → tok        ★ 整逻辑只此一次
        ├─【调用逻辑】getIdentityIdByAccount(tok, employeeId) → identityId
        ├─【If】!HasValue(identityId) 或 Get(identityId,0)<=0
        │     └─ result = "解析人员失败:${employeeId}" 【End 返回】
        ├─【SQL查询】SELECT * FROM SysTeacherInfo WHERE employeeId=${employeeId} LIMIT 1 → teacherRows
        │     （★ 方案B：单表 SELECT *、无 JOIN、无别名 ⇒ 不触发幻影类型 53724c75）
        ├─【If】!HasValue(teacherRows)          （🔴 列表判空只写 HasValue，别加 Length）
        │     └─ result = "未查到该工号所属学院:${employeeId}" 【End 返回】
        ├─【赋值】collegeId = Get(teacherRows, 0).college      🔴 漏这行 → 下面 SQL 拼出 departmentId = 直接报错
        ├─【SQL查询】SELECT * FROM SysDepartmentInformation WHERE departmentId=${collegeId} LIMIT 1 → deptRows
        ├─【If】!HasValue(deptRows)
        │     └─ result = "未查到该工号所属学院:${employeeId}" 【End 返回】
        ├─【赋值】collegeName = Get(deptRows, 0).departmentName
        ├─【If】!HasValue(collegeName)          （null 会让下面拼出 pathKey = 报错）
        │     └─ result = "未查到该工号所属学院:${employeeId}" 【End 返回】
        ├─【SQL查询】SELECT folderId FROM JyglHyFolderMap WHERE level=2 AND isDelete=0 AND pathKey=${collegeName} LIMIT 1 → l2FolderId
        │     （⚠️ 插 String 变量本身，勿写 Get(...) 表达式，否则报错）
        ├─【If】!HasValue(l2FolderId) 或 Length<=0
        │     └─ result = "未找到学院L2目录：${collegeName}" 【End 返回】
        ├─【调用逻辑】grantFolderPermission(tok, Convert<Integer>(Get(l2FolderId,0)), Get(identityId,0), 1, 9) → grantResult
        ├─【If】grantResult 有值（HasValue && Length>0，🔴 必须 &&）
        │     └─ result = "授权成功：${employeeId} → ${collegeName} L2"
        └─【Else】result = "授权失败：${employeeId} → ${collegeName} L2（grantFolderPermission 未返回成功）"
[结束]
```

> 📌 这是**方案 B**（两条单表 `SELECT *`）的蓝图，③ 由 1 个 SQL 组件变 **2 个 SQL + 2 次取值赋值 + 3 段判空**，详见 §4.3「落点对照表」。

> ✅ 两个逻辑**均无循环**，不触碰「循环内禁调接口」红线。

## 七、开放为接口的逐步操作（CodeWave IDE）

1. **建服务端逻辑**：在管理权限的应用里新建 `grantResidentL1` / `grantResidentL2`，按第五、六节拖组件（先搭 L1 再复制改 L2）。

4. **记下地址 + ak/sk**：集成中心 → 应用API管理 → 查看接口地址与请求定义（method/query/body）；ak/sk 与调用方约定。

## 八、外部调用示例

### 8.1 curl（GET + query）

`signature = md5(ak + sk + timestamp)`，timestamp 为当前 Unix 秒。CodeWave 开放接口**逻辑输入参数默认映射为 URL query**：

```bash
TS=$(date +%s)
SIG=$(printf "%s" "${AK}${SK}${TS}" | md5sum | cut -d' ' -f1)

# 授处长 L1
curl -G "{制品域名}/rest/grantResidentL1" \
  -H "ak: ${AK}" -H "timestamp: ${TS}" -H "signature: ${SIG}" \
  --data-urlencode "employeeId=41255" \
  --data-urlencode "roleName=教务处处长"

# 授院长/教秘 L2
curl -G "{制品域名}/rest/grantResidentL2" \
  -H "ak: ${AK}" -H "timestamp: ${TS}" -H "signature: ${SIG}" \
  --data-urlencode "employeeId=41255" \
  --data-urlencode "roleName=教学秘书"
```

> ⚠️ 实际 method / 参数位置以**导出后在 API 管理页看到的接口定义/swagger 为准**。
> ⚠️ **中文参数务必 URL 编码**（`--data-urlencode` 已处理），否则服务端收到乱码 → 角色校验失败。

### 8.2 另一 CodeWave 应用内调用

建第三方 API 分组 → 录地址 `{制品域名}/rest/grantResidentL1` → 定义 query 参数 `employeeId`/`roleName` → 选 akSkAuth 鉴权 → 「调用接口」组件调用。

## 九、注意事项 / 常见坑

1. **`permType` 必须显式赋 10**（若 `grantFolderPermission` 内部已处理则无需重复；确认其实现）。
2. 🔴 **SQL 组件插值只能插「变量本身」，不能写表达式/函数**（09-10 踩坑）：`sql"... WHERE pathKey = ${Get(collegeName, 0)}"` **报错**；必须先 `collegeName = Get(collegeNameList, 0)` 取出 String，再 `sql"... = ${collegeName}"`。可视化拖组件时从右侧面板**拖变量**进 SQL，勿手写 `Get(...)`。
2.1 **SQL 表名/字段名的写法「以本应用实测为准」**：本项目 SQL 组件**认实体大驼峰名**（`SysTeacherInfo` / `SysDepartmentInformation` / `t.departmentId` / `d.departmentName`，主人实测不报错）；而另一个应用的同步逻辑用的是**物理名**（`sys_teacher_info` / `department_id`，见 `docs/CW同步经验复用指南.md` §8.4）。**两种写法在不同应用/数据源下都可能成立，勿互相套用**；新写 SQL 时先跑一次验证，报「表不存在/列不存在」再换另一种。
2.2 **单列 SELECT → `List<String>`；多列 SELECT → `List<结构体>`**（字段名 = SQL 里的 `AS` 别名，取值 `Get(list,0).别名`）。本方案 ③ 只查一列，故 `collegeNameList: List<String>` + `Get(collegeNameList, 0)` 直接得字符串，**写法正确**。
3. **`folder_id` 列 VARCHAR(64)** → 传接口 `folderId`(integer) 前必须 `Convert<Integer>`。
4. **`memberType=1` 是个人授权**，不是职位（鸿翼无职位数据，09-10 已确认）。
5. **只授不撤**：本接口不做撤旧。换岗/离职的权限回收，调已有的 `removePersonPermission`。
6. **中文 roleName 校验**：入参是中文，注意 URL 编码；逻辑内比对用**精确相等**（`==`），不做模糊匹配。
7. **数据源边界（09-10 更正）**：不是「跨库 JOIN」问题。③ 的两张教务表**同库**可一条 JOIN；③（教务库）与 ④（讲义库）分属**两个数据源**，必须两条 SQL（CodeWave 不支持跨数据源 SQL）。前置 = 确认应用**配齐两个数据源**。
8. **开放接口 input 默认必填**；需要可空则给入参设默认值。
9. **发布后接口才生效**；改逻辑要重发布 + 调用方同步接口。
10. **幂等**：重复授同人同目录安全（鸿翼接受重复写）。

## 十、与既有逻辑的关系（全景）

| 逻辑 | 作用 | 授权目标 | 记账本 | 撤旧 | 形态 |
|---|---|---|---|---|---|
| `grantApproverPermission` | 审批时授权（讲义应用内） | 常驻 L1/L2 + 逐课 L4 | 逐课记 | 逐课撤旧 | 应用内逻辑 |
| `removePersonPermission` | **清权**（管理权限应用） | 清 L1+L2 全量 | — | — | **开放接口** |
| **`grantResidentL1`（本次新增）** | **授 L1 常驻** | L1 | ❌ | ❌ | **开放接口** |
| **`grantResidentL2`（本次新增）** | **授 L2 常驻** | L2（本学院） | ❌ | ❌ | **开放接口** |

> 📌 新增的两个接口 = `removePersonPermission` 的**反向操作**，三者构成「授/清」闭环，均由外部（管理员页面/其它应用）调用。
> `grantApproverPermission` 里的常驻授权段（B 段）与本次两个接口**功能重叠**——若两个接口上线并投入使用，B 段可作为审批时兜底保留，或后续精简（⚠️ 由主人决定，勿擅自删）。
